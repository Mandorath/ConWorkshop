# Lab Assignment: High-Level vs. Low-Level Container Runtimes

**Estimated Time:** 10 minutes
**Environment:** Rocky Linux VM with `sudo` privileges (No Kubernetes cluster required)
**Objective:** Manually separate the duties of a High-Level Runtime (image management and unpacking) from a Low-Level Runtime (kernel interaction and execution).

## Background

In modern Kubernetes environments (including Talos), "running a container" is split into two distinct jobs:
1. **The High-Level Runtime (e.g., `containerd`, `CRI-O`, `Podman`):** Talks to registries, downloads images, unpacks layers into a filesystem, and translates configurations. *It knows about networking and images, but it doesn't actually talk to the kernel to create the container.*
2. **The Low-Level Runtime (e.g., `runc`, `crun`):** Receives an unpacked directory and a JSON configuration file. Its *only* job is to configure Namespaces, Cgroups, and `pivot_root` (what you did manually in previous labs!), start the process, and then exit. *It knows nothing about image registries or networks.*

In this lab, we will play the role of the High-Level Runtime manually, and then hand the workload off to the Low-Level Runtime (`runc`).

## Step 1: Install Required Tools (1 min)

Ensure you have `podman` (our high-level tool for fetching) and `runc` (our low-level execution tool) installed on your Rocky Linux VM.

```bash
sudo dnf install -y podman runc
```

## Step 2: High-Level Runtime Duty - Image Management (3 mins)

First, we will act as the high-level runtime. We need to download an image from a registry and unpack it into a raw directory (`rootfs`).

1. Create a workspace for our OCI (Open Container Initiative) bundle:
   ```bash
   mkdir -p /tmp/oci-bundle/rootfs
   cd /tmp/oci-bundle
   ```

2. Use `podman` to pull a minimal Alpine Linux image, create a temporary container, and export its filesystem into our `rootfs` directory:
   ```bash
   # Pull from registry
   podman pull docker.io/library/alpine:latest
   
   # Create a dummy container to extract from
   podman create --name temp-alpine alpine:latest
   
   # Export the filesystem layers and unpack them into our directory
   podman export temp-alpine | tar -xf - -C rootfs
   
   # Clean up the dummy container
   podman rm temp-alpine
   ```

> **Observation:** Look inside the `rootfs` folder (`ls -l rootfs`). You will see a standard Linux filesystem. The high-level runtime's job of downloading and unpacking the image is complete.

## Step 3: High-Level Runtime Duty - Configuration (2 mins)

The low-level runtime needs instructions. It expects a standardized file called `config.json` that dictates exactly what Namespaces and Cgroups to apply.

Generate a default OCI specification file:
```bash
runc spec
```

> **Observation:** Run `cat config.json | grep -A 5 '"namespaces"'` or open the file in `vi`. You will see an array of namespaces (`pid`, `network`, `mount`, etc.). When you deploy YAML to Kubernetes, `containerd` translates your YAML into this exact JSON format.

## Step 4: Low-Level Runtime Duty - Execution (3 mins)

Now, we hand the bundle (`rootfs` directory + `config.json`) to the low-level runtime (`runc`). `runc` does not care where this data came from.

1. Execute the container using `runc`:
   ```bash
   sudo runc run my-manual-container
   ```

2. You are now inside the container! Verify the isolation:
   ```bash
   # Check OS release (should say Alpine, not Rocky)
   cat /etc/os-release
   
   # Check processes (You should be PID 1)
   ps aux
   ```

3. Open a **second terminal** on your Rocky Linux host and ask `runc` for the status of running containers:
   ```bash
   sudo runc list
   ```
   *(You will see `my-manual-container` running, managed by the low-level runtime).*

4. Go back to your first terminal and type `exit` to stop the container.

## Verification & Debrief

| Tool | Role in this Lab | Kubernetes Equivalent |
| :--- | :--- | :--- |
| **Podman / Tar** | High-Level: Fetched the image, merged layers, unpacked to disk. | `containerd` or `CRI-O` |
| **config.json**  | Contract: Defined the requested isolation boundaries. | Generated by `containerd` from Pod YAML |
| **runc**         | Low-Level: Created namespaces/cgroups and executed the shell. | `runc` (default in Talos/K8s) |

### Cleanup
```bash
sudo rm -rf /tmp/oci-bundle
```

### Core Architecture Takeaway
You have just executed the exact lifecycle of a Kubernetes Pod manually! When a Pod is scheduled on a Talos worker node, the `kubelet` tells `containerd` to pull the image and create the `config.json`. `containerd` then silently calls `runc` in the background to actually start the namespaces and spin up the container process.
